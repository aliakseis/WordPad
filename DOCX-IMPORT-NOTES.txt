DOCX importer update
====================

The DOCX importer reads ZIP packages directly in-process using zlib. It does
not use Shell.Application, IDispatch::Invoke, Folder.CopyHere, tar.exe, or an
external extraction process. XML parsing uses MSXML 6 on a dedicated STA
worker thread. COM interfaces are managed with ATL smart pointers.

Build requirements:
- Visual Studio 2022 / MSVC v143 and the MFC/ATL components.
- MSXML 6 (included with supported Windows versions).
- vcpkg with MSBuild integration enabled (run `vcpkg integrate install` once
  for the selected vcpkg installation, if it has not already been enabled).
- The included vcpkg.json manifest restores pinned zlib 1.3.1 automatically.
  The project selects static-library triplets and matches the CRT linkage to
  the MFC configuration (static CRT for Static MFC configurations, dynamic
  CRT for Dynamic MFC configurations). The MSBuild link step resolves the
  installed static library name and stages it under a stable local name.

The ZIP reader supports stored and Deflate entries, verifies CRC-32, and
rejects encrypted, multi-disk and ZIP64 packages, unsupported compression
methods, symbolic links/reparse points, duplicate paths, path traversal,
malformed headers, and unsafe Windows file names. The default 128 MiB
maxDocumentBytes option limits both the compressed package and aggregate
expanded file payload. maxImageBytes limits each embedded image, and generated
RTF is additionally bounded to approximately twice the package budget.
Package entries remain in memory; no extraction directory is created.

The Unicode-to-RTF conversion emits one fallback character for each RTF \u
control and never consumes the following source character. Embedded image
bytes are validated by PNG/JPEG signatures rather than trusting file names.
External hyperlinks are limited to HTTP, HTTPS, FTP, and mailto schemes;
DOCX table cell widths are retained when explicit twip widths are present.
Malformed relationship XML is reported instead of silently discarding every
image and hyperlink in the document.

zlib is linked statically; no zlib DLL or external extraction executable is
required. The source update has not been compiled in this environment. Build
the project in Visual Studio 2022 and test with representative DOCX files,
including non-ASCII characters followed by digits, images, tables, hyperlinks,
malformed ZIP/XML inputs, and packages near the configured limits.
